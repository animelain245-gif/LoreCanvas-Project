# Product Vision

## Final Requirement

LoreCanvas is an offline-first Android application for writers and story
planners to organize worldbuilding knowledge (characters, places,
relationships, history) as an interconnected, navigable system rather
than flat documents.

## User Purpose

Writers using flat documents (one giant character bio, one giant
worldbuilding doc) end up with knowledge that's hard to reuse, hard to
search, and disconnected from the actual story text. LoreCanvas treats
worldbuilding knowledge as structured, linked data instead.

## Required Behavior

- Fully functional with no internet connection (see
  `25-offline-first-requirements.md`).
- All project data stored locally, per-project, in a self-contained
  format.
- Two complexity modes: **Simple Mode** (approachable) and **Complex
  Mode** (exposes deeper worldbuilding functionality) — see
  `LoreCanvas-Project` instructions (already present in this repository
  at the project-instructions level, not just this ChatGPT record).

## Relationships With Other Systems

Everything else in this archive builds on this vision — the Node/Card/
Relationship/Timeline systems exist specifically to make "structured,
linked, offline worldbuilding knowledge" real.

## Historical Evolution

### Earlier Proposal
The project began under the working name **"Story Studio"** (see
`history/01_...md`, message #45).

### Revision
Several rebrand names were proposed: LoreForge (ChatGPT's stated
favorite), ChronoForge, StorySmith, InkAtlas, WorldWeaver, LoreCanvas,
ThreadForge, WriterHouse.

### Final Decision
The user chose the name directly: *"WriterHouse seem nice (But lore
forge and Lorecanvas are good too) Im going with lorecanvas"* —
`history/01_...md`, message #46.
